# 문서 사이트 (C8)

## When to Apply
- `docs/` 디렉터리의 파일을 추가/수정할 때
- 문서 사이트의 빌드/배포 설정(GitHub Actions, `pages` 워크플로우)을 수정할 때
- 공개 API의 시그니처/동작이 바뀔 때

## MUST
- 공개 API의 시그니처나 동작이 바뀌면 문서도 같은 PR에서 갱신한다
- 문서 사이트는 `docs/`에 단일 앱으로 구성한다 (GitHub Pages 호스팅)
- 문서 내 코드 예제는 실제 패키지 이름으로 import한다 (`@oon/foo`)
- 문서 사이트의 의존성은 라이브러리 패키지에 역영향을 주지 않는다 (의존 방향 준수)

## MUST NOT
- 라이브러리 패키지가 문서 사이트를 의존하지 않는다 (역방향 의존 금지)
- 문서에 존재하지 않는 API/옵션을 기술하지 않는다
- 깨진 내부 링크/앵커를 커밋하지 않는다

## PREFER
- API 문서는 TSDoc 주석에서 생성 가능한 형태로 작성한다
- 예제 코드는 실제로 빌드/테스트 가능한 형태로 관리한다 (doctest 또는 examples 패키지)
